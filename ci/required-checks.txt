# The required status-check contexts on `main` — the in-repo copy of what
# branch protection enforces, read by `cargo xtask ci-spec check`.
#
# Until 2026-09-05 this set lived only in GitHub's database, so nothing in
# the tree could ask "does every required context have exactly one producer,
# reported in the merge queue, that cannot be skipped?". Now it can.
#
# PINNED is the population pin and may only GROW. Removing a context is an
# owner decision: lower the pin in the same change and record why, dated,
# here. (The north-star ledger's two-direction convention.)
#
# `cargo xtask ci-spec live-parity` compares this file with the live branch
# protection; a mismatch is a red on the schedule, never a silent re-sync.
#
# 2026-09-09, 50 → 51: `Scoped Aeneas (Rust → Lean 4) — routing decision`. The
# scope check moved out of the expensive job into its own job on the CHEAP pool,
# so `runs-on` for the expensive one can be a function of the answer and the
# build pool is entered only when there is something to build. It ran 24s after
# waiting 442s for a slot (merge-group 60fa8483) and 18s after 792s (a37d21fa) —
# the critical path in both.
#
# It has to be REQUIRED, and `cargo xtask ci-spec check` is what said so: a
# required job that `needs:` a NON-required one is skipped when the upstream
# fails, and a skipped required check counts as passed, so a red routing job
# would VACATE the gate instead of blocking it. CI-I3-NEEDS. The pin grows,
# which is the allowed direction; the cost is one gate-pool context to stop
# holding a build-pool slot while deciding.

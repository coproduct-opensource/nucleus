# The required status-check contexts on `main` — the in-repo copy of what
# branch protection enforces, read by `cargo xtask ci-spec check`.
#
# Until 2026-09-05 this set lived only in GitHub's database, so nothing in
# the tree could ask "does every required context have exactly one producer,
# reported in the merge queue, that cannot be skipped?". Now it can.
#
# PINNED is the population pin and may only GROW. Removing a context is an
# owner decision: lower the pin in the same change and record why, dated,
# here. (The north-star ledger's two-direction convention.)
#
# `cargo xtask ci-spec live-parity` compares this file with the live branch
# protection; a mismatch is a red on the schedule, never a silent re-sync.
#
# 2026-09-09, 50 → 51: `Scoped Aeneas (Rust → Lean 4) — routing decision`. The
# scope check moved out of the expensive job into its own job on the CHEAP pool,
# so `runs-on` for the expensive one can be a function of the answer and the
# build pool is entered only when there is something to build. It ran 24s after
# waiting 442s for a slot (merge-group 60fa8483) and 18s after 792s (a37d21fa) —
# the critical path in both.
#
# It has to be REQUIRED, and `cargo xtask ci-spec check` is what said so: a
# required job that `needs:` a NON-required one is skipped when the upstream
# fails, and a skipped required check counts as passed, so a red routing job
# would VACATE the gate instead of blocking it. CI-I3-NEEDS. The pin grows,
# which is the allowed direction; the cost is one gate-pool context to stop
# holding a build-pool slot while deciding.
# 2026-09-09, owner decision, 50 → 47: `deny (advisories)`, `deny (bans)`,
# `deny (licenses)` and `deny (sources)` become the single context `deny`. The
# four were a matrix sharding ONE command (`cargo deny check advisories bans
# licenses sources`) across four jobs, each paying its own checkout, toolchain
# setup and pool slot. Nothing about what is enforced changes — `cargo deny
# check` with several categories reports each and still exits non-zero if any
# fails — so this removes three CONTEXTS, not three checks. The reason it is
# worth doing is in ci/merge-queue.toml: a single group's required contexts
# already saturate the pool, so four slots for one gate is four slots another
# gate waits for.
#
# 2026-09-10, merge of the two above: they compose rather than conflict. From 50,
# main's deny fold removed three contexts (-> 47) and this branch's routing
# decision adds one (-> 48). Neither number alone is right on the merge; 51 was
# computed against a 50-context main that no longer exists.
# 2026-09-17, owner decision (the hard cut to gatehouse, fail closed), 48 -> 47: `Rustfmt` and
# `Clippy` leave, `gatehouse/required` joins. The two GitHub jobs are replaced by the gatehouse
# plan's `fmt` and `clippy` gates, which run the same commands (clippy: the all-features workspace
# run AND the crate-scoped portcullis run) inside a protected Firecracker microVM on gatehouse's
# builder; each run's receipt is signed at NodeAttested and verified before the required context
# can go green. `gatehouse/required` is produced by the coproduct-gatehouse GitHub App (4853870),
# not a workflow, so it carries `@app`: the producer and merge-group invariants cannot be decided
# from the tree for it, and live parity instead holds branch protection to that app id. It also
# requires the plan's `ci-spec` and `test-core` gates; `Tests` stays required here because it
# additionally runs the SDK tests (node, python) that the gate image does not carry.
# 2026-09-20: 47 -> 38. The SECOND SUBTRACTION of the 2026-09-17 cutover, nine lines late.
#
# `ci/gatehouse-replacements.txt` records eleven contexts retiring to the gatehouse `text-gates`
# gate, and says what retiring one costs: "a line out of ci/required-checks.txt and a rule out of
# the GitHub ruleset". The ruleset subtraction happened; this one did not, so for weeks
# `live-parity` reported nine CI-LP-MISSING and the gate that reports it was itself not required.
#
# Read from this side alone the drift looks like GitHub having lost nine required contexts, and
# that is how it was first read today -- the nine were ADDED to branch protection, taking it to
# 47, before `gatehouse-replacements.txt` turned up and said they had been retired on purpose.
# Branch protection has been returned to the 38 it held; this is the file that was wrong.
#
# The nine still RUN -- ci.yml's `text-gates` job and its relays are untouched -- and they still
# gate a merge, through `gatehouse/required`, which is context 14 here. What changed in September
# is which context carries them, not whether anything does.

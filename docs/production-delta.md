# Production Delta

What must be true before Nucleus can be called enterprise-ready. This page consolidates gaps from [SECURITY_TODO.md](../SECURITY_TODO.md), [FORMAL_METHODS.md](../FORMAL_METHODS.md), and [Verified Claims](verified-claims.md) into one checklist.

## Hardening

| Item | Status | Detail |
|------|--------|--------|
| Egress confinement (proven) | Partial | The enforcement boundary for shell effects is the network policy, not the effect layer: one `(RunBash, BashExec)` authority buys arbitrary syscalls in the guest and `bash -c 'curl \| sh'` never reaches `NetEffect::fetch`. The CIDR/port matcher is now Aeneas-extracted and 8 theorems are proven over it ([EgressConfinementExtracted.lean](../crates/portcullis-core/lean/EgressConfinementExtracted.lean)), all `[propext, Classical.choice, Quot.sound]`, zero `sorry` — including `unmatched_is_dropped` (nothing passes unless a rule admits it) and `deny_before_allow_wins`. `net::egress_chain` returns the chain as an ordered **value** consumed in one pass, so the Lean fold corresponds to the applied order by construction rather than by hope. **Open:** that iptables implements these semantics and applies the rules at all is trusted, not proven; the conntrack/loopback baseline rules are outside the model. **Corrected:** earlier drafts of this row said DNS-tunnelled exfiltration was untouched. That overstated the exposure — see the DNS proxy row. What remains is exfiltration *to an allowlisted host over an allowed connection*, which no network policy can prevent by construction. |
| DNS proxy is a static map, not a resolver | Done | A DNS tunnel needs a *forwarder*: the agent encodes data in query labels and the resolver carries them to the attacker's authoritative server, invisible to the egress allowlist because the query went to the allowed resolver. nucleus's dnsmasq config has **no upstream at all** — `no-resolv` and not one `server=` — so an unlisted name fails locally instead of travelling. This was true by accident of how the config string was built; `dnsmasq_config` is now a pure function and `the_dns_proxy_has_no_upstream_and_cannot_forward` makes it a property, so adding a forwarder is a test failure rather than a silent re-opening. Also covered: an empty allowlist answers nothing rather than falling back to forwarding. |
| Workload identity gated on egress confinement | Done | A SPIFFE SVID bounds how **long** a credential is useful; nothing bounded **where** it could be presented. A pod with `allow: ["0.0.0.0/0"]` held an identity presentable to any endpoint, attacker's included. `net::decide_identity_grant` now withholds the workload API from a pod whose allowlist reaches public space without naming a host — every `allow` entry must stay in non-routable space (any breadth) or be a `/32`. `dns_allow` is unaffected: it resolves to `/32`s. Absence of a policy **grants**, because that is default-deny with no allow rules — the most confined state, and denying there would invert the incentive. Offered as a trade, not a ban: the pod still boots, without an identity. Enforced on **both** sides: the vsock port is withheld (`workload_api_port_for`) *and* the pod is never registered with the workload API (`identity_registration`), so a guest that guessed the port finds nothing to fetch — `WorkloadApiServer` issues against registered connections. Both compositions are extracted from the Linux-gated spawn path so they compile and test on any host. **Open:** the two call sites inside `spawn_firecracker_pod` are `cfg(target_os = "linux")` and are covered by the musl CI job, not locally — verified by probe that they are not compiled on macOS. |
| microVM snapshot/restore + warm pool | Not started (guard landed) | **Measured** on Apple M5 Pro → Lima `vz` → KVM → Firecracker 1.16.1 with the real API: cold boot to userspace **79 ms**, snapshot create **151 ms** (256 MiB mem file), **snapshot restore+resume 7 ms** with the plain `File` backend (UFFD not yet used). An 11x improvement and competitive with the fastest agent-sandbox platforms, so this is worth building. **Not built.** What landed first is the refusal: nucleus injects per-pod secrets — `approval_secret`, `auth_secret`, `sandbox_token`, `task_token_hex/issuer/nonce`, AWS credentials — **on the guest kernel command line**, so they are baked into `/proc/cmdline` and the snapshot memory image. Restoring N pods from a post-boot snapshot would give all N the same approval secret and the same **nonce**: an authority leak between tenants, since the task token authorises the in-VM tool proxy. Firecracker's VMGenID re-seeds the guest kernel PRNG on resume but explicitly does **not** de-duplicate identifiers, tokens or nonces. `snapshot::snapshot_safety` refuses any cmdline carrying per-pod material, and `every_cmdline_key_is_classified` fails if a new `nucleus.*` key is added without being classified — so a new secret cannot default to "clonable". **Open:** the snapshot/restore path itself, the warm pool, and the post-restore channel for delivering per-pod material off the command line. |
| Guest holds no HMAC key (CB4A Phase 1) | Done | `nucleus.auth_secret` is no longer emitted onto the guest kernel command line. It was an HMAC key protecting the host↔proxy channel, but both live in the same VM and `/proc/cmdline` is world-readable — a trust boundary drawn inside one trust domain. Replaced by kernel-enforced peer identity: the proxy's vsock listener drops any peer whose CID is not `VMADDR_CID_HOST`, and the guest kernel sets that CID. **Measured**: with `vsock_loopback` loaded an in-guest loopback connect succeeds and arrives as CID 1, never 2. `auth::select_auth_tier` pins precedence exhaustively because a reordering would silently make the transport tier dead code. **Open:** `nucleus.approval_secret` is still emitted — the approval path is drand-anchored and freshness is not origin, so dropping it needs a drand-only tier first. |
| PDP/CDP separation of duties (CB4A) | Done (structural) | CB4A requires that the policy decision point never touch credential material and the credential delivery point never decide policy. Enforced two ways: **cross-crate**, `deny.toml` lists `nucleus-cred-broker` with `wrappers`, so a policy crate depending on it fails the existing `deny (bans)` gate — verified by perturbation (`error[banned]`); and **inside the composition root**, where the ban cannot help because both halves legitimately link, by signatures — `pdp_decide` takes no store, `cdp_fetch` takes no lattice. `Credential` has no `Serialize` impl (serialisation is how a value would cross into the guest), a redacted `Debug` that hides length as well as value, and `ZeroizeOnDrop`. |
| Credentials in the guest spec | Partial — exposure re-mapped | The original claim was that the exposure is uniform: the full PodSpec lands in the guest, so every credential is readable. **Tracing each driver shows that is wrong per driver, and the difference is what has kept `cred_split` from having a call site.** Firecracker: the node writes NO guest spec (`build-rootfs.sh` bakes it at image build time) and injects no `credentials.env` at all — nothing to strip, which is why `check_enforcement_is_honest` refuses `--broker-enforcing` there. Container: injects credential values **directly as container environment variables**, readable via `docker inspect` and `/proc/PID/environ` and inherited by every child the agent spawns — strictly worse than a file — but it has no per-pod vsock, so `decide_rollout` returns `Disabled` and there is no broker to ask instead. That is the deadlock, now stated plainly rather than left as a missing call site: **the driver this was built for has nothing to strip; the driver that carries the exposure has no transport.** `only_the_container_driver_injects_credential_values` pins the map against `main.rs` and fails in both directions. Closing it needs the container driver to gain a broker socket — a bind-mounted Unix socket would do, it has no vsock but it does have a filesystem — which is real work, not a wiring oversight. |
| Broker identity binding | Done | The guest cannot state who it is. `TaskRequestEnvelope` has no identity field — an earlier version had `pod_identity` and the host built its `AuthorizedRequest` from it, so a guest could name any pod and be decided for it. Identity is now `PodIdentity`, which has **no `Deserialize` impl**, so it cannot arrive from the wire at all; it is bound to the **listener**, once, because Firecracker creates one vsock `uds_path` per VM and a socket therefore IS a pod. Perturbation: adding `#[derive(Deserialize)]` makes the `compile_fail` doctest fail, establishing it depends on the missing impl rather than on a typo. |
| Broker socket on the live path | Done (ListenOnly) | `--broker-listen` serves a per-pod broker socket bound to the identity the node minted, owned by `FirecrackerPod` and torn down with it. Owning the handle is load-bearing, not tidiness: the socket path derives from the pod's vsock path, so a listener outliving its pod would still speak for the **dead** pod when a later pod reused that path — `a_reused_socket_path_does_not_inherit_the_dead_pods_identity` fails if the unlink is removed. Teardown returns `ShutdownOutcome` so the stop signal is itself testable; an earlier version returned nothing and its test passed with the signal removed. **Limit:** the store is empty until `cred_split` has a call site, so every request is currently refused, and the guest's client is not yet called. |
| Witness completeness — no effect without a receipt (FM-3) | Done | Two halves. **Structural:** `Authority::spend` now REFUSES an unwitnessed spend (`SpendError::Unwitnessed`) rather than performing it silently — the fail-open shape NIST SP 800-53 AU-5(4) names and CB4A states outright for credential issuance. Checked before the scope check, so a missing log cannot hide behind a policy error. **Completeness:** the drift guard `authority.rs` had named for months, `every_effect_is_witnessed`, **had never been written**; it now exists as `every_policy_enforced_method_routes_its_authority_through_the_witness`, scans the source rather than exercising paths, and asserts non-vacuity first. Turning the spend fail-closed found the one real bypass in the workspace: `Sandbox::spend_as` spent directly rather than through `PolicyEnforced`, so every sandbox write left no record — six tests failed, which is how it surfaced. `Sandbox` now owns a log, and both the allowed and the refused write are recorded. **Limit:** `ReceiptLog::append` cannot fail (in-memory `Vec`), so "issuance fails if the log write fails" is still not expressible; it becomes real when the log gains a durable sink. |
| PDP/CDP separation as call-graph reachability (FM-2) | Done (half) | CB4A states its two MUSTs as prose about components; `tools/nucleus-cb4a-lint` states them as reachability — nothing reachable from a PDP root may name credential material, nothing from a CDP root may name policy. Closes **forward** from named roots, where the sibling `mediated` pass closes backward from I/O. Clean on `nucleus-node`, `nucleus-cred-broker`, `nucleus-tool-proxy`, `portcullis-effects`, and that clean result rests on three perturbations that each produced a report — including a two-hop violation whose every intermediate signature is clean, which is the case a type check cannot reach. **Half, precisely:** a forward closure stops at the crate boundary, so past it the property rests on the `deny.toml` `wrappers` ban instead. Neither half is sufficient alone. **CI:** `.github/workflows/dylint-separation.yml` runs both passes on Linux. `cb4a_separation` is **enforced at zero** — and by counting reports, not by exit status, because `cargo dylint` exits 0 even when a `Warn` lint fires (verified: a perturbed PDP produced a finding and exit code 0, so a job trusting the exit status would have passed any number of violations through). `mediated` is reporting-only while its 15 known `portcullis-effects` findings stand; suppressing them to get green would be worse than not running it. |
| `sandbox_token` off the cmdline for identity-bearing pods | Done | Tier 3 of `sandbox_proof` is the fallback for a workload with **no** SPIFFE identity; a pod that gets one proves itself from its SVID and never reads the token — so emitting it there put a per-pod secret on the world-readable kernel command line to be ignored. Now emitted only when `workload_api_port` is `None`, which is exactly the identity predicate rather than a proxy for it: `net::workload_api_port_for` and `net::identity_registration` are the same rule (identity enabled AND grant granted) stated on the advertising and serving sides. **Conditional, not a removal** — a node with identity management off, or a pod whose grant was denied, has Tier 3 as its *only* proof and `sandbox_proof` exits fatally when no tier succeeds, so deleting it outright would turn those pods from working into dead. This needed no booted pod, which is what the earlier note assumed: the question was never "does attestation succeed" (Tier 2 suffices) but "does the guest get an SVID at all", and that is decided in code. Tests are Linux-gated because `from_spec` is; verified in OrbStack, and perturbed back to unconditional emission to confirm they bite. |
| Guest identity on the live path | **Two ordering defects fixed, both boot-found** | **(1)** `spawn_firecracker_pod` started the workload API bridge *after* `wait_for_proxy_health` — the guest's SVID source produced only once the guest was already healthy, while the guest needs it *in order* to be healthy. Survivable only because `nucleus.sandbox_token` gave a host-independent Tier 3 proof; the moment that became conditional, every identity-bearing launch failed. The block is moved before the health check and `the_workload_api_bridge_starts_before_the_health_check` pins it against the source, so a regression fails a test rather than deadlocking a fleet. **(2)** With the fetch finally succeeding, a second defect surfaced that the first had masked: `guest-init` writes the SVID to `/etc/nucleus/identity` and **never told the proxy where it was** — `NUCLEUS_IDENTITY_CERT` went unset, so Tier 1/2 reported "no identity cert" with the cert on disk. Both verified end to end through the real `nucleus-node` on KVM: the guest now logs its SPIFFE ID, fetches its task token over vsock, and starts without the naked-process FATAL. **Open:** `wait_for_proxy_health` still times out — a host-side layer (the signed proxy reaching the guest) not yet isolated. |
| Full pod launch through the node | **Succeeds end to end** | On real hardware, `CREATE: 200` with the node log showing the whole chain in order: workload API bridge started (before the health check), identity registered, guest fetching its SPIFFE ID and its session token over vsock, pod spawned. The earlier timeouts were a mix of a health budget that predated the guest's host round-trips and stale state (a leftover Firecracker holding the fixed `/run/firecracker.socket`). **Known limit, now legible rather than opaque:** a second concurrent launch fails with "vsock socket not found" because the node uses a fixed API socket path, so without the jailer only one pod launches at a time. `HealthProbe` is what makes that readable — the probe used to collapse a refused connection, a `401`, a `502` and a dead guest into one "timed out" message. |
| Task token over vsock (FM-4 enabler) | Done (fetch path); cmdline copy still emitted | `FETCH_TASK_TOKEN` added to the workload API's closed command enum — adding a variant is the only way to teach the host a new command, and the compiler enforced exhaustiveness at three sites when it landed. The host serves the same three values the cmdline carries; a pod with no minted token gets an explicit refusal rather than `{"token":""}`, because the tool-proxy treats missing and invalid differently. The guest fetches **synchronously before `exec_proxy`**, which is the ordering risk that made this need hardware — **verified on a booted pod**: with the task token stripped from the kernel command line entirely, the guest logged `fetched session task token over vsock` and the proxy started without panic. **Cmdline copy retained as fallback on purpose:** the guest side and protocol are boot-proven, but the node's own serving path was exercised by a host stub rather than by `nucleus-node`, so removing the fallback would rest on an untested leg. When it goes, a fetch failure must become fatal — the tool-proxy would otherwise start tokenless and fail closed far from the cause. |
| Snapshot / warm-pool payoff (FM-4) | Not arrived — distance now measured | The plan called this "a consequence, not a workstream": remove per-pod material and `snapshot_safety` becomes satisfiable by construction. **That was wrong.** Phase 1 deleted exactly one key (`nucleus.auth_secret`); **five remain** — `approval_secret`, `sandbox_token`, `task_token_hex`, `task_token_issuer`, `task_token_nonce` — so a realistic pod command line is still refused and the warm pool is still blocked. `the_remaining_distance_to_a_snapshottable_base_is_five_keys` pins the exact set as a ratchet in both directions: adding one fails, removing one fails until the distance is re-stated. (It also caught its own author: the first version asserted four, because the shell pipeline used to count deduplicated `task_token_nonce` away — which is the argument for pinning the set rather than the number.) Next removal identified with its precondition: `sandbox_token` is Tier 3 of the sandbox proof, verified with an `auth_secret` no longer delivered on this path, but deleting it makes every pod depend on Tier 1/2 attestation succeeding — an empirical claim needing a booted pod on the KVM box, not a code reading. |
| Approval TTL (Phase 3) | Done | An `AuthorizedRequest` had no expiry, so a PDP verdict was a **standing grant**: a decision made once stayed true forever, and a value that leaked into a cache, a log, a retry queue or a long-lived task authorised the same fetch indefinitely. It now carries `expires_at_unix` (60s, matching CB4A's own worked example), checked in `for_request` **before** the store lookup — so a stale approval never touches credential material, and an expired request for a registered target takes the same path as one for an unregistered target rather than differing in timing and logs. Time is a parameter, not an ambient read: one instant judges one request, and the TTL is tested by choosing instants rather than by sleeping. Verified by perturbation, including a second round — the first version of the ordering test passed with the lookup moved first, because with a *registered* target both orderings refuse; it now uses an expired approval for an *unregistered* target, which is the case that separates them. **Not done:** DPoP sender-constraining, which applies to tokens leaving the host — none are issued yet, so there is nothing to bind. The envelope-layer analogue (binding the approval to a host-observed identity) is closed, see *Broker identity binding*. |
| Broker transport is no longer vsock-only | Done (predicate); container broker blocked deeper than wiring | `decide_rollout` keyed on `has_vsock`, making the container driver structurally unable to have a broker — the driver that actually carries the credential exposure. Now `BrokerTransport::{None, Vsock, PodDirSocket}`, and a container needs **no new mount** because `spawn_container_pod` already bind-mounts the pod directory. `prepare_socket` refuses any path naming a container runtime socket (`docker.sock` and friends): mounting one into an agent sandbox is the canonical escape. **The remaining obstacle is not wiring.** `broker_identity` refuses a pod with no host-established identity, and the container driver registers none — there is no identity-manager call on that path. Giving containers one is not glue: a Firecracker identity comes with an attested SVID and a default-deny netns, and a container has neither, so the identity would assert what the driver cannot back — the same defect as letting a guest name itself, one level up. |
| Identity gate — claim corrected | Done | `broker_launch` claimed "identity is only registered when the pod's egress is confined enough to hold one, so a pod with unconfined egress cannot obtain brokered credentials at all." **That overstated the gate.** `net::decide_identity_grant(None)` returns `Granted` — a pod with *no* network policy is registered; what gets refused is a policy whose `allow` list names a broad public range. The composition holds where a driver default-denies a pod that declared no policy (the Firecracker netns path) and not in general — and the container driver rejects structured network policy outright, so its pods always pass `None`. `a_pod_with_no_network_policy_is_still_granted_an_identity` pins the real rule so the prose cannot drift back. |
| Guest boots on real KVM | **Found two defects no test could** | A pod built by this repo's own `build-rootfs.sh`, booted on the KVM box under Firecracker 1.16.1: **(1)** the tool-proxy **panicked as PID 1**, taking the kernel with it, because `DrandClient::new` used `.expect()` and a Debian-slim rootfs ships no system CA store — drand is enabled by default, so this hit every pod. The message named reqwest, not the missing CA store. `new` is now fallible; the guest exits with an actionable message, the node degrades loudly. **(2)** `build-rootfs.sh` installed no CA bundle at all; it now copies one from the build host. Both verified by re-boot: the proxy went from dying at 1.5 s to running 5.5 s and exiting *gracefully* on a missing NIC (a harness limitation, not a defect). All 436 tests passed before **and** after — they run on hosts that happen to have a CA store, which is exactly why a boot was needed. Also observed: with `nucleus.auth_secret` gone from the cmdline and no baked `/etc/nucleus/auth.secret`, **Tier 3 sandbox proof cannot verify**, so a pod with no SVID cannot start — confirming the reasoning behind the conditional emission. Residual, stated not implied: reqwest's builder still panics internally if no rustls crypto provider is installed, which this signature change does not cover. |
| Credential noninterference (FM-1) | Done | Seven theorems over the Aeneas-extracted delivery relation ([CredentialNoninterferenceExtracted.lean](../crates/portcullis-core/lean/CredentialNoninterferenceExtracted.lean)), all `[propext, Classical.choice, Quot.sound]`, zero `sorry`, **0 opaque functions**. A credential is never deliverable to the guest; the guest cannot distinguish `Internal` from `Secret`, so it cannot learn a credential exists. Includes non-vacuity — a broker that refused everything would otherwise satisfy the theorem. `native_decide` was used and then removed: it adds `Lean.ofReduceBool`, and kernel-external evaluation under this theorem would undermine it. Verified by perturbation: raising the guest's ceiling in the **Rust** breaks the Lean proof after re-extraction. **Limit:** says nothing about whether the implementation consults the relation, nor about timing or size channels. |
| Receipt log resilience (FM-3) | Done (scope corrected) | `ReceiptLog::append` panicked on a poisoned mutex, as did every read path — so one pod's panic would make every subsequent spend panic, turning a logging problem into a node-wide outage. Removed; recovery is justified for this append-only structure specifically. **The plan's fail-closed audit is NOT implemented and is not pretended**: the log is an in-memory `Vec`, a push cannot fail, and a `Result` that can never be `Err` would look like a guarantee and provide none. Fail-closed becomes meaningful when the log gains durable backing. |
| Command exfiltration detection beyond program-name | Partial | `bash -c 'curl ...'` bypasses. Default command lattice blocks common flags; broader coverage and fuzzing pending. Firecracker network policy is the backstop. |
| Path sandboxing: unicode + symlink races | Partial | Symlink escape test added for `work_dir`; unicode NFC/NFKC normalization and Windows path edge cases not fuzzed. `cap-std` provides defense-in-depth. |
| Budget enforcement atomicity | Partial | Pre-exec reservation works. Post-exec cost accounting and output-based charges not implemented. A process can run even if budget is exhausted. |
| Approval tokens: anti-automation | Done (type-level) | `ApprovalToken` required for gated ops. Callbacks only mint tokens. No structured proof-of-human (e.g., signed challenge) yet. |
| Discharge scope binding | Done | Every mediated `NucleusRuntime` method checks the bundle's `(Operation, SinkClass)` against its own, and `write_file` re-checks the path allowlist. Previously the bundle was accepted unread, so a read bundle authorized a write and could redirect it outside `allowed_write_paths`. The predicate is now proved over the Aeneas-extracted Rust ([claim 8a](verified-claims.md)) with a clean axiom set. |
| Enforcement completeness (#1216) | Done (effect layer) | **All 13 effect-trait methods take an `Authority` by value** — scoped, and one-shot by move semantics, so replay is a compile error. Before this work 10 of 13 took no obligation token at all and 3 took a `&DischargedBundle` that could be replayed. Ownership is threaded through `nucleus::Executor` (10 signatures) and `nucleus-tool-proxy`. Residual, out of scope here: the `nucleus::Sandbox` surface, tracked in its own row below. |
| Effect receipts (witness) | Partial | Every mediation decision through `PolicyEnforced` appends a leaf to an RFC 6962 Merkle log naming the `(Operation, SinkClass)` and the outcome. Supports **inclusion** proofs (`O(log n)`), **consistency** proofs, an Ed25519-signed checkpoint, and a **witness** verification core (C2SP `tlog-witness` checks) that refuses to cosign a checkpoint which is not a provable append-only extension — closing split-view/fork detection. Append-only by construction. **Coverage is all 13 effect methods.** The receipt is written by `Authority::spend` rather than at the gate, so the three that spend further down — `run_argv`, `run_argv_async`, `NetEffect::fetch` — are witnessed where they consume the authority; previously process execution and network egress were the only effects *absent* from the log. Because `Authority` is affine and `spend` is the only way to consume one, "the authority was exercised" and "a receipt exists" are the same event. **Open:** a receipt records an authorised spend, not a completed effect — `Allowed` is written upstream of the syscall, and splitting *authorised* from *committed* needs a post-effect event that is not implemented; attaching the witness is still a call the mediation layer makes, so a new forwarding method that omitted it would enforce correctly but log nothing (guarded by `the_deferred_spend_methods_are_witnessed_where_they_spend`, whose dependence was established by perturbation); the witness is a verification core, not a running service (no HTTP, no persistence, no origin multiplexing); no public anchoring; the signing key is caller-supplied and **not bound to a measured binary**. |
| `Sandbox` mediation | Done | All 22 `DecisionToken`-taking `Sandbox` methods now require an owned `Authority` and spend it against the operation they declare — reads against `(ReadFiles, AuditLogAppend)`, edits and writes against `WorkspaceWrite`. Previously only `write`/`write_approved` took a discharge and both ignored it (`_proof`, zero reads), so any bundle authorized a write and `remove_file` deleted with no discharge at all. The HTTP and MCP read paths had no discharge either; both now mint one via `run_gate::preflight_read_fs`. Not covered: `exists`/`exists_approved` return `bool` with no error channel, so mediating them is a signature change rather than a check; and `read_to_string_for_search` takes no `DecisionToken`. |
| `NucleusRuntime::effects()` escape hatch (#1248) | Open | Returns raw `PolicyEnforced` bundle without obligation discharge or FlowTracker update. |
| Type-level IFC not composed into runtime API (#1249) | Open | `read_file()` returns `Vec<u8>`, not `Labeled<Vec<u8>>`. Runtime and compile-time IFC are independently correct but not wired together. |

## How to Read This Page

- **Done**: implemented, tested, CI-gated.
- **Partial**: works for common cases, known gaps documented.
- **Implemented**: code exists, minimal testing.
- **Open**: tracked in a GitHub issue, not yet addressed.
- **Acknowledged**: known limitation with no current plan to close (e.g., Aeneas toolchain limitation).
- **Not started**: no work has been done.

This page is updated with each release. If you find a gap not listed here, please [file an issue](https://github.com/coproduct-opensource/nucleus/issues).

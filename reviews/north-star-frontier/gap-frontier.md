# Clause 5 gap analysis — "continuously expand the frontier of safely delegatable agency"

Date: 2026-09-08. Static read of `/home/user/nucleus` and `/home/user/gatehouse`; every line reference below was opened and read, not taken from the internal maps. Nothing modified.

## 0. Framing

Clause 5 asks a project to *measure* the safely-delegatable envelope (work completable under a formally specified authorization at zero contract-forbidden effects), *ratchet* it in both directions (safety may not regress; capability may not regress), *publish* it (a scoreboard of what can be delegated today), and *grow* it through a repeatable process (new effect classes get mediated, proved and shipped; denials feed back into policy). The SOTA reports converge on the same five artefacts: a versioned utility-ratio-vs-envelope chart at ASR=0 validated by adaptive attack (sota-agent-security §5), least-agency/OPUR and stage metrics, auto-approved/escalated/denied shares with time-to-approval (sota-formal-oversight B6), TCB and coverage disclosure, and a frontier-metrics API (sota-agent-protocols §6.7).

Nucleus has an unusually honest and mechanised *safety* ledger — and essentially nothing on the capability side. Every ratcheted number in the tree is monotone in containment or proof hygiene. The one instrument that measures work lost to enforcement (`nucleus-flow-replay`'s sink split) prints to stderr inside a unit test; the one lever that would recover work (graded taint response) is an env flag defaulting to off that nothing sets; the one external benchmark bridge raises `NotImplementedError` at construction; and the perf/friction ledger's most recent live measurement is that a `codegen` pod could neither read nor write.

## 2. The gaps (ranked by how much closing them would expand safely delegatable agency)

### G1 — No utility-under-authorization metric; every ratchet is monotone in containment (architectural + measurement)
Evidence: `crates/xtask/src/scoreboard.rs:18-32`; `scripts/north-star-ledger-ratchet.txt`; `scripts/check-north-star-ledger.sh:47-53`; `docs/north-star.md` status table C1–C9; `crates/nucleus-flow-replay/tests/sink_consequence_split.rs` (asserts `>0`, prints to stderr); `docs/production-delta.md:82`; repo-wide grep for utility/frontier/false-refusal returns only research-file hits.
SOTA: utility ratio at fixed ASR (PACT 38-46% at 100% security; AUTHGRAPH 0.69 at ASR 0.01; CaMeL 67/77 vs 84 undefended); "no published work defines an authorization-envelope vs utility Pareto frontier" (sota-agent-security §4); frontier chart versioned per release (§5.1).
Direction: promote `ReplaySummary` to a first-class artefact `frontier.json` = per canonical profile {steps, allowed, requires_approval, denied, ceiling_attributable, denied_at_local_reversible, recovered_by_graded} over a pinned, growing task corpus; add it to the exemplar scoreboard as HIGHER metrics (`allowed_share`, `recovered_share`) with a `_GUARD` partner (`corpus_steps_GUARD` may not fall, `denied_at_exfil_vector` may not fall) so utility cannot be bought by shrinking the corpus or opening exfil sinks; publish a per-release chart. Impact critical; effort medium (the crate, the summary and the ratchet harness all exist).

### G2 — The external-benchmark bridge is dead and single-model (implementation)
Evidence: `benchmarks/agentdojo/portcullis_defense/defense.py:96,110` `raise NotImplementedError(_MIRROR_REMOVED)`; `pyproject.toml` depends only on `agentdojo`; no workflow references agentdojo/portcullis_defense; `make_divergence_corpus.py:33-77` collapses ~80 tools to 14 operations plus `synthetic:` sinks; `red-team-agent.yml` single `vars.LLM_MODEL`; `red_team_harness.rs` canary-only.
SOTA: AgentDojo triple (benign utility / utility under attack / targeted ASR) per model and policy tier; report for ≥3 vendors + one open-weight model (sota-agent-security §5.5); cross-architecture comparison on a shared harness is itself novel (§5.7).
Direction: give `GuardedRuntime.run_function` a real kernel: either a `nucleus-flow-replay` stdin/HTTP server mode (`--serve`) that accepts one `TraceStep` per call and returns the verdict, or a PyO3 binding (the workspace already carries `portcullis-python`, excluded at `Cargo.toml:90`); run 4 suites × 4 attacks nightly across a model matrix with `LLM_MODEL` as a strategy dimension; write (utility, security) pairs into `frontier.json` (G1). Impact critical; effort large.

### G3 — The only utility lever is dormant and un-principled (implementation + architectural)
Evidence: `crates/portcullis/src/kernel/ifc.rs:96,122-130` (`NUCLEUS_GRADED_TAINT`, default OFF, read from process env per decision); no launcher, spec or certificate field sets it; `exposure_core.rs:716-734` grades by `default_sink_class(op)` only; `sink_consequence_split.rs:3-5` "100% of refusals attributable to the session-wide taint ceiling".
SOTA: FIDES/PACT/AUTHGRAPH enforce at argument-provenance granularity; PORTICO "controlled grants recover work a fixed envelope blocked"; type-directed privilege separation extends the securable set.
Direction: (a) move the graded response out of the process environment into the authorization object — a monotone field of `PermissionLattice`/`ProfileSpec` (ungraded ≤ graded), signed in the certificate and re-verified per hop, so a principal (not an operator env) authorizes it and it shows up in receipts; (b) extend `TaintResponse` from sink-class to (sink, argument provenance) using the `FlowGraph` nodes the kernel already tracks, so an outbound action whose *arguments* derive only from trusted nodes is not refused because the *session* saw web content; (c) pin `recovered_share` from `report_what_grading_would_change` in `frontier.json`. Impact high; effort medium.

### G4 — No feedback loop from denials to policy proposals, and no operational counters (implementation)

## 3. What to borrow from gatehouse for clause 5
- The `ready`/`vacuous`/`disagreeing` verdict rule for any capability ratchet (a utility number measured only on a corpus that never refuses anything is not evidence).
- Cost-of-checking as a frontier metric (`cost-ceilings.txt`): nucleus should pin verify-per-hop latency (chain depth × ms) and per-call kernel decision cost alongside utility.
- DECIDED as a status between TESTED and PROVED, with a founding-defect fixture, for the frontier ledger rows that are decision procedures over the real tree (e.g. "every canonical profile completes its fixture task").
- Admission-before-Required: a new effect class or profile becomes "delegatable" only after its e2e fixture and cost are measured (`docs/executor.md:141-143`).

# Gap analysis — Clause 2: "as much useful real-world work"

Date: 2026-09-08. Static reading of /home/user/nucleus and /home/user/gatehouse (no builds). Every claim below was re-verified in source; where an internal map was stale I say so.

Clause 2 asks two things: (a) breadth and depth of effects a principal can hand over — fs, shell, net, git, MCP tools, browser, cloud APIs, payments, messaging, long-running and multi-step work, memory across sessions — and (b) the friction of doing so (approvals, setup, latency, tiers). The failure mode is not "the agent did too much" but "the runtime refuses, or cannot mediate, work the principal WOULD authorize", or mediation so coarse that operators turn it off (`--dangerously-skip-permissions` on the host is exactly that: `crates/nucleus-cli/src/run.rs:1061-1062`).

## One-paragraph verdict

Nucleus's mediated effect surface today is: seven file/search/web tools plus argv-only exec, reachable through one vendor CLI, with the exec tool broken on the wire; credentialed APIs, git push, PR creation, email, cloud, tickets, payments, browser and third-party MCP tools either have no op-level capability or have a proxy path that the shipped runner never exposes. Every outbound effect is refused the moment any web content enters the session unless an env flag nobody sets is on. Approvals cannot be obtained in the isolated tier and, on the HTTP path, do nothing when obtained. Pods live one `timeout_seconds` with no resume, no persistent memory, and no sub-agent spawn. The one live-pod exercise on record (`docs/perf/RUBRIC-LEDGER.md` rows 2/2b) found a `codegen` pod that could neither read nor write. Against the SOTA (Claude Code/Codex OS-sandboxed full shells, Sandlock's TLS-terminating egress with credential injection, MCP 2026 per-hop token exchange, AP2/SPT payment mandates, CaMeL/FIDES value-level provenance at 67-77% utility, Firecracker 7 ms restore), the envelope of *safely delegatable* work nucleus can actually deliver is narrow and the friction to use it is high. The good news: the structural core behind the proxy (sealed effects, Authority spend, cap-std, netns) is sound, so most gaps are "expose and widen" rather than "rebuild".

## Gaps (ranked by expected expansion of the safely-delegatable envelope)

### G1. The default exec path is dead on the wire, and the exec model cannot express shell work
**Kind:** implementation (with an architectural tail). **Impact:** critical. **Effort:** small (wire) / large (shell-in-fence).

Evidence:
- `crates/nucleus-mcp/src/main.rs:93-96` — `RunRequest { command: String }`; tool schema at `:875-882` advertises `{"command": string}`; `:1170-1181` POSTs that to `/v1/run`.
- `crates/nucleus-tool-proxy/src/main.rs:896-905` — proxy `RunRequest { args: Vec<String>, stdin, directory, timeout_seconds }`, no `#[serde(alias)]`; grep for `alias|"command"` in the proxy finds nothing. The shipped `run` tool therefore cannot deserialise → 4xx on every call. Fail-closed, but exec utility on the default path is zero.
- `crates/nucleus-tool-proxy/src/main.rs:903-905` — `timeout_seconds` is `#[allow(dead_code)] // Reserved for future timeout implementation`: even the argv form has no caller-controlled timeout.
- `crates/portcullis/src/command.rs:46-51,87,100` — `allow_metacharacters: false` by default; pipes, `&&`, redirects are refused; the classifier re-splits joined argv (`crates/nucleus/src/command.rs` executor path) and detects git/PR effects only by argv shape (`crates/nucleus/src/command.rs:945-956`: `git push`, `git commit`, `gh pr create`), so `git -C dir push`, `make release`, scripts and `xargs` fall into the generic `run_bash` bucket.
- `crates/nucleus-cli/src/run.rs:1068-1098` — `build_mcp_allowed_tools` grants `mcp__nucleus__run` whenever any of run_bash/git_commit/git_push/create_pr ≥ LowRisk, so a principal who authorised only `git_commit` gets an exec tool whose real ceiling is the argv classifier.
- Tier 1: `README.md:284` admits spawned commands are bare host processes; `crates/nucleus-tool-proxy/src/pod_mgmt.rs:388-400` declares `ContainmentMode::Unsandboxed` even in the VM (attestation TODO), so any policy asking for `microvm()` isolation refuses to run *inside the VM*.

SOTA: Claude Code and Codex run a *full* bash under an OS boundary (Seatbelt / bubblewrap+Landlock+seccomp) with a domain-allowlist proxy, and only escalate on the ~5% of calls the sandbox cannot contain (sota-agent-protocols §3; sota-formal-oversight B1 "80-15-5"). Sandlock (DSN 2026) freezes the task for TOCTOU-safe `execve` inspection instead of string-classifying argv (sota-isolation §2). ActPlane enforces on indirect execution paths at 1.9-8.4% overhead.

Direction: (1) accept both `{"command"}` and `{"args"}` on `/v1/run` (alias + shell-words split behind the existing metachar policy) and add a contract test that `nucleus-mcp`'s serialised request round-trips through the proxy's type; wire `timeout_seconds`. (2) Move exec authority from argv-shape classification to the fence: inside the microVM (Tier 2) or under Landlock+seccomp (Tier 1), let `bash -c` run with the lattice compiled to static kernel policy (paths from `PathLattice`, net from `NetworkSpec`), and keep the argv classifier only as an obligation hint for `git push`/`gh pr create`. (3) Derive `ContainmentMode::MicroVM` from the verified `SandboxProof` so `minimum_isolation` policies stop refusing in the VM.

### G2. Credentialed real-world APIs (git push, PRs, cloud, SaaS, payments) have no reachable path
**Kind:** architectural. **Impact:** critical. **Effort:** medium.

Evidence:
- The only credentialed effect is `POST /v1/egress/{name}/{*path}` (`crates/nucleus-tool-proxy/src/main.rs:2096-2099`, `egress.rs:225-260`): fixed base URL per named upstream, header injected host-side from the *node's* environment (`crates/nucleus-node/src/broker_launch.rs:277-300`), idempotency key mandatory. This is a good design — but `nucleus-mcp` exposes no tool for it: its tool list is `read, write, run, web_fetch, glob, grep, web_search, create_pod, list_pods, pod_status, pod_logs, cancel_pod` (`crates/nucleus-mcp/src/main.rs:850-993`); `grep egress` in nucleus-mcp finds only an error string (`:542`). The Python SDK and OpenClaw plugin do not call it either. Zero examples declare `credentialed_egress` (`grep -rl credentialed_egress examples docs sdk` → two design docs only).
- No git credential path exists anywhere: `grep -rl 'git-credential|GIT_ASKPASS|credential.helper|askpass' crates` → empty. In Tier 2 the guest holds no secrets by design (`nucleus-spec/src/lib.rs:796-816`) and has no DNS without `dns_allow` (`net.rs:318-320`), so `git_push` and `create_pr` — two of the 13 lattice operations, with their own approval obligations and Kani/Lean coverage — cannot be performed end-to-end in the isolated tier at all. The `codegen` profile comment (`crates/portcullis/profiles/codegen.yaml:5`) makes "human pushes" the workflow.
- `egress.rs:152-180` `reject_bypassable_upstreams` refuses to boot if an upstream host is also on `network.allow` — correct, but it means a principal cannot give the shell `github.com` *and* have a credentialed GitHub API; they must choose.
- The broker's `PerformRequest` carries only `(target name, path, body)` (`egress.rs:330-332`); there is no method/path ACL per upstream, no OAuth token exchange, no per-hop scoped token, no spend cap. `crates/nucleus-recompute/src/cart.rs` models an AP2 Cart Mandate but nothing on the effect path consumes it (sota-agent-protocols weaknesses list).

SOTA: MCP 2026-07-28 mandates RFC 8707 audience binding and RFC 8693 exchange so each hop gets its *own* downstream token; Auth0 Token Vault and Okta Cross-App Access do the exchange; Claude Code's sandbox proxy masks credentials with sentinel substitution and SigV4 re-signing; Sandlock injects credentials post-ACL behind a TLS-terminating proxy; Stripe SPT / Mastercard Agentic Tokens attenuate amount/merchant/expiry at issuance (sota-agent-protocols §1.1, §2.2, §4; sota-isolation §4).

Direction: (1) Expose `egress` as an MCP tool and SDK method; add a `git-credential` helper (and `GIT_ASKPASS`) in the guest that obtains a per-push short-lived token through the broker, so `git push`/`gh pr create` become real mediated effects in Tier 2. (2) Extend `CredentialedEgressSpec` with method+path-glob ACLs, a per-upstream call/amount budget, and an optional RFC 8693 exchange (`act` = pod SPIFFE id) so the token the upstream sees is minted for *this* hop. (3) Route AP2/ACP mandates through the same broker as a `payment` upstream class whose ACL is the mandate's constraints. (4) Ship one example PodSpec per upstream class (GitHub API, S3, a ticket tracker) and a live test that a `safe-pr-fixer` pod opens a PR.

### G3. The effect vocabulary is frozen at 13 ops; email, cloud, tickets, browser, payments and third-party MCP tools cannot be authorised at profile level or constrained by argument
**Kind:** architectural. **Impact:** high. **Effort:** large.

Evidence:
- `crates/nucleus-ifc-kernel/src/ifc_ops.rs:23-52` — `Operation` is 13 discriminants frozen for Aeneas; `SinkClass` (`:220-262`) has 19 classes incl. `EmailSend`, `CloudMutation`, `TicketWrite`, `MCPWrite`, `SearchIndexWrite`, `MemoryPersist` — reachable only via `PolicyRuleSet`/`classify_sink`, never as a capability a principal sets.
- `crates/portcullis/src/profile.rs:84-125` — `CapabilitiesSpec` YAML has exactly the 13 fixed fields; no `extensions` map, so the declarative language cannot name a third-party tool at all. `docs/permissions.md` and the Python mirror still say 12.
- The signed tool surface exists (`crates/portcullis/src/tool_surface.rs:1-40`, extension keys = tool name + schema digest, monotone under meet) but its only consumer is `nucleus-mcp-guard` (`proxy.rs:360`), an operator-run stdio proxy whose taint classification is substring-on-tool-name (`classify.rs:36-40`), outside `check-mediation.sh` scope and never launched by `nucleus run`.
- `Kernel::decide(op, subject: &str)` (`crates/portcullis/src/kernel.rs:1125`) takes a single string subject: there is no argument-level constraint ("send only to @corp.com", "amount ≤ 50", "only repo X") except `SinkScope.allowed_git_refs/hosts/paths` in the cert. Cedar/CEL bridges exist but have no callers (read-authz-model §1).
- No browser or computer-use effect exists (grep → OIDC/agent-card hits only).

SOTA: Progent's JSON-schema DSL over tool names + argument constraints (ASR 25.8→4.2% at preserved utility); PACT/AUTHGRAPH per-argument provenance roles (100% security at 38-46% utility, 8-16 pts above CaMeL); Cedar in front of every AgentCore tool call (GA Mar 2026); AuthZEN MCP Tool Authorization profile; UCAN `pol` arg predicates; remote browser isolation (Firecrawl/OpenClaw) with egress through the same proxy (sota-agent-security §2.3/2.6; sota-authz-tokens §4, §6.1c; sota-isolation §4).

Direction: (1) Add `tools:` and `sinks:` sections to `ProfileSpec` that populate `CapabilityLattice.extensions` (tool name+digest → level) and per-sink-class levels, so a principal can write `email_send: low_risk` or `mcp:jira/create_issue: always` in YAML and it lands in the signed cert. (2) Add a generic `/v1/tool` route in tool-proxy that mediates an arbitrary MCP `tools/call` (name, args JSON) through the kernel with the tool's SinkClass and a caveat check over args (start with the existing CEL `constraint::Policy`, keep the decidable-meet subset), and expose it in `nucleus-mcp` so third-party servers are mediated on the default runner, not only behind an operator's stdio guard. (3) Add a `browser` effect as a remote-browser upstream whose egress goes through G7's proxy. (4) Keep the 13-op core frozen for the proofs; prove the extension meet/`Never`-absent rule (already the design) and DRT the arg-caveat evaluator Cedar-style.

### G4. The session-wide taint ceiling makes every outbound effect unusable after any web read; the graded response exists but is off and unmeasured
**Kind:** implementation + measurement. **Impact:** high. **Effort:** medium.

Evidence:
- `crates/nucleus-flow-replay/tests/sink_consequence_split.rs:3-5` — "100% of refusals are attributable to the session-wide taint ceiling — once any adversarial content is observed, all outbound actions are denied regardless of what they would do." This is the only utility measurement in the repo and it is a test that prints to stderr.
- `crates/portcullis/src/exposure_core.rs:207-240` — `ifc_egress_verdict(.., graded)`; with `graded=false` any `OutboundAction` in a tainted session is `Deny`. `crates/portcullis/src/kernel/ifc.rs:126-130` — `graded_taint_enabled()` reads `NUCLEUS_GRADED_TAINT`, default **false**; nothing in `nucleus-cli`, PodSpec or profiles sets it. So the shipped behaviour is the binary ceiling.
- Taint is session-level, not value-level: `web_fetch`/`web_search` results are observed into the single `FlowGraph` (`web_search` handler `main.rs:4121-4123`; memory recall `memory.rs:11-16`) with no typed extraction or per-value labels, so a research-then-edit task (`research-web` profile) cannot end in a commit.
- The only way back is governor-signed declassification (`/v1/declassify`, keys from node env, fail-closed when empty — `main.rs:1885-1900`) or k-of-n `SignedDeclassify` — neither is an agent- or principal-facing flow.

SOTA: CaMeL keeps 67% (strict) / 77% (tiered) of AgentDojo utility vs 84% undefended by carrying capabilities per *value*; FIDES adds `query_llm` quarantined reasoning and a task taxonomy of what taint tracking can secure; type-directed privilege separation turns untrusted strings into closed typed values; PACT/AUTHGRAPH reach ASR≈0 at utility ratio 0.69 with per-argument provenance (sota-agent-security §2.1-2.6). Nobody publishes an envelope-vs-utility frontier — the pieces are here.

Direction: (1) Make `graded` a PodSpec/profile field (default on for pod-local reversible sinks) and put `denied_at_local_reversible` from `ReplaySummary` (`flow-replay/src/lib.rs:135-165`) into `scoreboard.json` as a ratcheted "utility recovered" number. (2) Add per-value labels: a quarantined typed-extraction tool (schema-validated JSON from web content) whose *outputs* carry `Untrusted` but do not raise the session ceiling, mirroring FIDES/CaMeL; the sink check then consults the argument's label, not the session's. (3) Give the principal a declassify path that is an approval, not a governor ceremony (ties to G5). (4) Revive the AgentDojo runner through `nucleus-flow-replay` (`benchmarks/agentdojo/portcullis_defense/defense.py:96,110` refuses at construction today) and report utility/utility-under-attack/ASR per profile.

### G5. Approvals cannot be obtained where they are needed, and do nothing where they are obtained
**Kind:** implementation. **Impact:** high. **Effort:** medium.

Evidence:
- `crates/nucleus-tool-proxy/src/mediation.rs:161-190` — code comment for #2406: `http_kernel_decide` returns `RequiresApproval` before the sandbox path that reads `ApprovalRegistry`; "An operator who grants an approval here gets a 200 and no effect". Confirmed on read.
- Tier 2: `crates/nucleus-cli/src/run.rs:704-710` hands `nucleus-mcp` `auth_secret: None, approval_secret: None`; `crates/nucleus-mcp/src/main.rs:329-336` `post_approve` falls back to `auth_secret` → posts unsigned; the proxy in enforced mode requires an Ed25519 approver signature with a drand round (`auth.rs`, `RUBRIC-LEDGER.md` row 2c). So the only human UI — a `/dev/tty` `[y/N]` prompt (`nucleus-mcp/src/main.rs:1382-1398`) — can never succeed in the isolated tier, and in Tier 1 the secret it uses lives in a temp `mcp.json` any allowed `run` can read (read-enforcement §3.4).
- Approvals are one-shot counters, not envelope changes: `call_with_approval` sends `count: 1` (`nucleus-mcp/src/main.rs:1363-1369`); `approve_operation` stores `(operation string, count, expiry)` and records the grant with `ActorIdentity::Unknown` (`main.rs:4341-4350`). Nothing signs a new attenuation block, so the audit chain does not show *who* widened *what*.
- `/v1/escalate` (`escalate.rs:200-235`) mints an `EscalationGrant` and returns it; `grep -c kernel escalate.rs` → 0: the grant is never applied.
- Live evidence: `RUBRIC-LEDGER.md` row 2 — `write_files: low_risk` in `codegen` returned `403 approval_required` and the harness could not proceed.

SOTA: approval fatigue measured at ~97% reflexive approval; the answer is fewer, richer, asynchronous approvals — AuthZEN AARP, CIBA / MCP elicitation URL-mode, PORTICO epoch-bound grants that *extend* the envelope and are removed on closure, AP2's two-level intent→cart mandate where the second signature is auto-issuable when the first's predicates hold (sota-formal-oversight B1-B2; sota-agent-protocols §1.1, §4; sota-authz-tokens §6.4; sota-agent-security §2.8).

Direction: (1) Fix #2406 by making `http_kernel_decide` consult `ApprovalRegistry` (or, better, return `RequiresApproval` only to the retry path that does). (2) Replace the counter with a signed *approval block*: the approver's Ed25519 signature over `(cert fingerprint, op, subject caveats, count, exp)` appended as a `DelegationBlock` (or third-party block, per Biscuit) so the widened envelope is in the chain and the receipt names the approver. (3) Give `nucleus run` in Tier 2 an approver identity: a host-side approver key (`/var/lib/nucleus/state/approval_signing_key.der` already exists per row 2c) driven by a pluggable channel — TTY, webhook, CIBA — with SLA timeout that fails closed. (4) Apply `EscalationGrant` to the kernel as a bounded attenuation delta, or delete the endpoint.

### G6. Path scoping is blocklist-only and mis-rooted, so a principal can neither grant "write only src/**" nor get a pod that can read its own workspace
**Kind:** architectural + implementation. **Impact:** high. **Effort:** medium.

Evidence:
- `RUBRIC-LEDGER.md` rows 2/2b (2026-09-02/03): on a live `codegen` pod "There is no file in the sandbox a `codegen` pod may read"; `/work` → `403 sandbox_escape` "so `/work` is NOT the sandbox root despite being the spec's `work_dir`"; the lattice permits the paths but the pod's effective policy refuses, and the message names a layer not a rule (#2400).
- `crates/portcullis/src/profile.rs:208-215` — `PathsSpec.allowed` "Empty means all allowed"; all ten shipped profiles use `blocked:` only (`crates/portcullis/profiles/codegen.yaml:35-43`). The task token deliberately ships `allowed_paths` empty because the two semantics are inverted (`crates/nucleus-node/src/session_mint.rs:35-41`, "Paths (deferred)").
- Delegation path subsumption is a hand-rolled structural glob compare (`crates/portcullis-core/src/delegation.rs:48-66` `glob_covers` → `glob_subsumes_segments`); gatehouse learned the hard way that spelling-based subsumption is wrong and moved to a kernel-checked semantic `globSubsumes` (`/home/user/gatehouse/prelude/ci.writ:44-45`, `crates/writ-kernel/src/lib.rs:716`).
- Tier 1: `run` commands see the whole host filesystem; only file *tools* are cap-std fenced (read-enforcement §3.1); `run` handler checks only `directory`, not args (`tool-proxy/main.rs:3806-3820`).

SOTA: Landlock (ABI v6/v7, 6.19 pathname sockets) gives static, kernel-enforced, TOCTOU-safe path authority; Sandlock keeps path authority static and uses COW only for reversibility; AgentFS-style COW overlays give per-op policy and undo; gatehouse's `Cap.fsRead/fsWrite` glob sets ordered by semantic subsumption and checked by a verified kernel (sota-isolation §2, §4; read-gatehouse §2).

Direction: (1) Make `work_dir` the sandbox root in the guest (fix #2400/#2401) and add a boot-time self-test that a fresh pod can read and write one file under `work_dir` under every shipped profile. (2) Give profiles `paths.read_allowed` / `paths.write_allowed` with allowlist semantics, lift them into cert `SinkScope.allowed_paths` and the task token, and compile them to Landlock rules for `run` children in both tiers. (3) Replace `glob_covers` with a semantic subsumption oracle (port gatehouse's `globSubsumes` or prove the existing one) and put it under Kani/Lean since it is on the delegation path.

### G7. Network for real work: no DNS by default, IPs pinned at boot, no egress proxy for shell traffic, no host scope in profiles
**Kind:** architectural. **Impact:** high. **Effort:** large.

Evidence:
- `crates/nucleus-node/src/net.rs:318-320` — `start_dns_proxy` returns `None` when `dns_allow` is empty: a Tier 2 pod has *no resolver*; `cargo fetch`, `npm install`, `pip install`, `git clone` all fail unless the operator enumerates hosts. `resolve_dns_allowlist` (`net.rs:983-1009`) resolves each host to IPv4 once at pod start and pins the set into iptables — CDN-backed hosts (crates.io, npm, GitHub) rotate, so allowlists go stale mid-task; IPv6 is disabled outright.
- Shell egress is netns-backstopped only (`docs/architecture/mediated-set.md` rows 5/10 per read-formal): no proxy sees `curl`/`git`/`cargo` traffic, so there is no credential injection, no method/path ACL, no receipt, and no lattice decision for it — which is why G2's `reject_bypassable_upstreams` has to forbid allowing the host at all.
- `web_fetch_policy.rs:38-41, 80-83` — empty `dns_allow`/`url_allow` means allow-all; no private-range/metadata block in the checker (only a test constructs 169.254.169.254). In Tier 1 (`run.rs:653` `network: None`) this is an open SSRF surface.
- `ProfileSpec` has no host/network dimension; only PodSpec `NetworkSpec` (`nucleus-spec/src/lib.rs:312-326`) does, so the principal's *profile* cannot say "this agent may reach docs.rs and api.github.com".
- gatehouse: `hermeticCap` (`prelude/ci.writ:76-77`) requires `net == None` and zero secrets for **every** gate; `gatehouse-agent/src/lib.rs:137` refuses any secret. CI work that needs the network (dependency fetch, deploy) is out of the envelope by construction; the executor works only through a pre-populated bare mirror (`docs/executor.md:86-93`).

SOTA: the 2026 consensus (Sandlock, Anthropic sandbox-runtime, Vercel, Azure ACA Sandboxes, Codex) is remove-netns-or-redirect → per-sandbox proxy, deny by default, TLS-terminate when method/path policy is needed, inject credentials at the proxy, and run an allowlist-aware DNS forwarder *inside* the netns (codex #22387). Codex's two-phase model (network during setup, offline after) is the low-friction default for coding work (sota-isolation §4, §5).

Direction: (1) Always run the in-netns DNS forwarder, resolving only allowlisted names and re-resolving on TTL rather than pinning boot-time IPs. (2) Add a transparent egress proxy on the gateway (nftables redirect of 80/443) that consults the lattice/`SinkScope.allowed_hosts` per connection, terminates TLS for upstreams that declare method/path ACLs, and injects credentials there — this is the same broker as G2, made reachable to the shell. (3) Add `network:` to `ProfileSpec` so host scope is in the signed cert, not only the PodSpec. (4) Block private ranges in `web_fetch` regardless of allowlist; ship a Codex-style "setup phase online, task phase offline" preset. (5) For gatehouse: add a `Pinned` net cap that the executor enforces via nucleus's proxy so `cargo fetch` gates become admissible.

### G8. Long-running, multi-step, multi-session work: pods die with their timeout, memory is in-process, sub-agents cannot run code, and start-up is seconds not milliseconds
**Kind:** architectural. **Impact:** medium-high. **Effort:** large.

Evidence:
- `crates/nucleus-node/src/pod_authority.rs:314` — certificate TTL = `spec.timeout_seconds`; `session_mint.rs:72` binds the task token to the same TTL. There is no renewal, re-delegation on resume, or checkpoint: a task that outlives its estimate loses all authority.
- Snapshot/restore and warm pools: `docs/production-delta.md:12` — measured (restore+resume **7 ms**) but "**Not built**"; the refusal that landed is correct (per-pod secrets on the kernel cmdline would clone), the post-restore secret channel is open.
- Memory across sessions: `/v1/memory/write|recall` exist (`tool-proxy/main.rs:2109-2110`) but the store is `ProvenanceMemorySet::new()` in `AppState` (`main.rs:497-498, 1905`) — in-process, per-pod, no persistence; `nucleus-mcp` exposes no memory tool (tool list `main.rs:850-993`), so no agent on the default runner can use it.
- Sub-agents: `AgentSpawnEffect::spawn` is `NotImplemented` (`portcullis-effects/src/lib.rs:767-777`); `create_sub_pod` strips any requested workload (`pod_mgmt.rs:707-713`) so a sub-pod is a proxy with no agent in it; pod routes exist only when a node client is configured (`main.rs:2117-2124`).
- Latency/scale: `docs/perf/agent-tool-call-isolation.md:20-28` — 5,580 ms submit→running, 5-pod burst ceiling (N=10 → 10/10 only in 74 s after #2415); the rubric's goal of one microVM per tool call is at row 2 FAIL.

SOTA: Firecracker snapshot restore 5-30 ms with warm pools is table stakes (E2B, Vercel, Fly); Kubernetes Agent Sandbox has pause/resume, persistent storage and scheduled deletion; PORTICO's epoch-bound grants are renewed per closure predicate, not per wall-clock; "Delegation Without Trust" bounds a compromised sub-agent by task scope (sota-isolation §2, §5; sota-agent-security §2.8).

Direction: (1) Certificate renewal: the node re-issues a same-or-narrower child cert on a `/v1/renew` from the pod's holder key while the principal's root mandate is still valid, so TTL is a heartbeat not a guillotine; log each renewal as a lineage edge. (2) Persist `ProvenanceMemorySet` keyed by principal+trust-domain on the node with recompute-verified admission on load, expose `memory_write/recall` in `nucleus-mcp` (the MemoryPersist sink class already exists). (3) Build the snapshot pool with a post-restore vsock secret delivery (the `every_cmdline_key_is_classified` guard already forces the design). (4) Let `create_sub_pod` carry a *derived* workload (the parent's own image + attenuated cert) so orchestrator profiles actually orchestrate; keep the IFC ceiling wiring from SECURITY_TODO §11.

## Cross-cutting notes

- Measurement (clause 5 overlap): the only utility instruments are `flow-replay`'s stderr split and `nucleus observe` (least-privilege profile from traces, `crates/nucleus-cli/src/observe.rs:1-4`). Neither is tracked. Each gap above should land with a number in `scoreboard.json`: `run` round-trip success under each profile, credentialed effects completed, tasks completed per profile with ASR=0, approvals requested/granted/median latency, utility recovered by grading.
- Vendor coupling (clause 1 overlap) multiplies every friction here: the only runner is one CLI with `--dangerously-skip-permissions`, and the `--hook` tier depends on a private crate (`README.md:284`).

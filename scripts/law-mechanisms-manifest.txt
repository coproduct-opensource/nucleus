# Law-mechanism manifest — mechanisms that are DECLARED but not WIRED.
#
# Read by `cargo xtask law-mechanisms` (crates/xtask/src/law_mechanisms.rs) via
# the shim scripts/check-law-mechanisms.sh.
#
# WHY THIS FILE EXISTS
#
# A 2026-09-09 architectural audit asked whether nucleus's operational concepts
# are instances of shared algebraic objects. They mostly are. The finding that
# mattered was different: most of those unifications are ALREADY BUILT, several
# are machine-proved, and they are not wired to the enforcement path. The gap
# between the proven algebra and the running enforcement is where the live
# defects were.
#
# The repo already knew this class in two narrower places — docs/north-star.md
# demoted clause C9 because "the attested-cert producer is dead-code with its
# result discarded", and scripts/check-extracted-callsites.sh (C8) gates it for
# the Aeneas predicates: "a predicate proven about a function nobody calls is a
# proof about dead code." This file is the general case.
#
# WHAT A ROW MEANS
#
#   CLASS | LAW | mechanism | decl_anchor | use_anchor | file | note
#
# Class D — declared, with no live call site. The gate asserts, over the
# production region (tests/, benches/, examples/, fuzz/, *_tests.rs and
# #[cfg(test)] blocks all excluded) of every file `git ls-files` reports:
#
#   1. `decl_anchor` still appears in the declaring file — a row whose
#      mechanism was renamed or deleted is stale, and a stale row is itself a
#      finding;
#   2. `use_anchor` appears NOWHERE else. A row that becomes wired FAILS, and
#      the fix is to delete the row and lower DEAD_COUNT.
#
# TWO anchors, not one, because a definition and its call sites never share a
# literal: the file says `pub fn with_isolation`, callers say
# `Kernel::with_isolation(`. A single anchor made check 1 pass on whatever doc
# comment happened to mention the qualified name, which is passing by accident.
# The use form must also be qualified enough not to collide: `with_isolation(`
# alone would match `PolicyContext::with_isolation` and
# `WeakeningCost::with_isolation`, which are unrelated methods.
#
# So the list may only shrink, and it shrinks by wiring the mechanism or by
# deleting it. Both are progress. DEAD_COUNT is exact: a slack pin lets a row
# vanish unnoticed, which is the failure this gate exists to catch.
#
# ANCHORS MUST BE UNAMBIGUOUS LITERALS. This is a grep, not a resolver, so a
# method whose call site is `x.extend(...)` cannot be anchored — the literal
# would match every Vec in the tree. `TimeLattice::extend` is dead (no non-test
# callers) and is deliberately NOT listed for that reason; recording an anchor
# that over-matches would make the gate lie in the safe-looking direction.
#
# Adding a row is not a way to park a mechanism. A row is a debt with a name.
